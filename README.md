# 星火 · 报修派单与配件台账

Web 前端开发课程项目，为星火义务维修队 12 名队员制作的单机演示小站。

每周三下午，在大学生活动中心免费维修台灯、风扇、插线板等小物件。页面把工单、负责人、维修进度和配件余量放到同一个工作台上。

## 如何运行

无需安装依赖。直接用 Chrome 或 Edge 打开仓库根目录的 `index.html` 即可。

也可以在仓库根目录启动静态服务器（本机已安装 Python 时）：

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

然后访问 `http://127.0.0.1:8080`。本地文件与 HTTP 地址的浏览器存储互相独立；换浏览器或地址不会共享记录。

## 演示账号

- 队长：选择「林一 · 队长」。
- 队员：选择其余任意队员，例如「陈晨 · 电工组」。
- 所有账号密码：`xinghuo123`，登录页已预填。
- 点右上角账号可以退出登录，再选择其他角色。

12 名队员、10 张工单和 5 类配件均为**虚构的模拟数据**，不代表真实维修队记录。种子工单日期为打开页面时最近的周三。

## 当前可用功能

- 登录：队长 / 队员角色切换，按角色显示操作入口。
- 工作概览：本周工单、待接单、本周完成率、队员数。
- 工单登记：填写送修人、联系方式、物品、故障、维修组和送修时间，自动生成编号。
- 四列看板：待接单 / 维修中 / 待配件 / 已修好，支持搜索与小组筛选。
- 工单详情：负责人、送修信息与带时间戳的维修时间线。
- 接单与进度：队员只能更新自己负责的单；队长可指定负责人。
- 配件台账：固定名称与规格字典，领用扣减、归还增加、队长登记入库。
- 我的工单：当前队员负责的工单。
- 队长后台：各组及队员本周工作量、配件余量、本周工单与耗材 CSV 导出。
- 本地保存：刷新后，工单、进度、登录状态和配件记录仍在。
- 窄屏布局：导航横排，看板改为两列。

## 试用顺序

1. 用队长账号进入，浏览看板和配件台账。
2. 点「登记工单」，录入一个台灯故障。
3. 在详情中点「由我接单」，或者选择队员进行派单。
4. 打开自己负责的工单，登记领用配件，并更新为「待配件」或「已修好」。
5. 刷新页面确认保存；到「配件台账」查看库存和流转记录。
6. 退出，换队员账号，查看「我的工单」与权限差异。
7. 用队长账号进入「队长后台」，下载本周 CSV。

## 文件结构

```text
index.html              页面骨架、登录和表单
css/style.css           样式与响应式布局
assets/favicon.svg      星火图标
js/data/seed.js         虚构的演示数据
js/data/store.js        数据访问层、校验、角色约束、本地存储
js/ui/app.js            页面渲染、交互与 CSV 下载
docs/立项报告.md         已提交的立项报告（保留原文）
docs/项目日志.md         实现范围与后续计划
```

技术为 HTML + CSS + 原生 JavaScript，无框架、无构建步骤、无外部 CDN。使用经典脚本，方便直接双击 HTML 运行。

页面只通过 `XinghuoStore` 的异步方法访问数据；`localStorage` 读写集中在 `js/data/store.js`。后续接后端时，可以将这些 Promise 接口改为 `fetch` 请求。

## 版本边界

这是单机课程演示：账号密码在前端，仅用于展示角色差异。数据保存在当前浏览器，不提供正式认证、跨设备共享、多人抢单锁、自助查询或消息通知。

本周统计从周一开始，工单以送修时间计入；配件流转按实际记录时间计入。当前余量只是本地台账，没有联网库存预警。所有维修服务免费。

重新演示初始数据时，先导出所需记录，再在浏览器开发者工具中删除 `xinghuo-repair-demo-v1` 本地存储项并刷新。清除会移除这个浏览器地址下的全部演示记录。
