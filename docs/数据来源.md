# 公开资料整理说明

## 范围与规则

收录全国图鉴编号 001—151 的默认形态，不收录地区形态与其他特殊形态。属性与基础能力采用采集时 PokéAPI CSV 的现行数据；包含现行妖精属性，不表示使用第一世代游戏规则。

项目不编造宝可梦参数，也没有内置假的个人收藏、个人队伍、练习成绩或访问量。两个演示账号的个人记录初始为空。另有作者设计的静态参考队伍，用于提供挑战内容；它们与个人记录分开展示，不冒充真实玩家的提交。

## 资料来源

结构化数据来自 <https://github.com/PokeAPI/pokeapi/tree/master/data/v2/csv>：

- `pokemon.csv`：编号、英文标识、默认形态、原始身高体重。
- `pokemon_species.csv`：物种与上一阶段进化关系。
- `pokemon_species_names.csv` 与 `languages.csv`：匹配简体中文名与分类名称。
- `pokemon_types.csv`、`types.csv`、`type_names.csv`：角色属性及中文属性名。
- `pokemon_stats.csv`、`stats.csv`：六项基础能力。
- `type_efficacy.csv`：攻击属性到防御属性的倍率表。

图片来自 <https://github.com/PokeAPI/sprites> 的 `sprites/pokemon/other/official-artwork/`，保存为 `assets/pokemon/编号.png`。文档为 <https://pokeapi.co/docs/v2>。

## 转换与可追溯性

身高的原始单位为分米，除以 10 得到米；体重的原始单位为百克，除以 10 得到千克。基础能力总和是六项能力相加。

`tools/build_catalog.py` 整理资料并生成 `js/data/catalog.js` 与 `assets/data/source-manifest.json`。后者记录下载日期、数据与图片仓库版本、每个 CSV/图片的 URL 和 SHA-256。

脚本优先查询提交版本。GitHub 匿名 API 限流时，来源标为 `master`，以下载快照与逐文件摘要记录实际内容；这时它不是固定提交快照，不能将 `master` 误称为提交 SHA。已下载源文件缓存于被 Git 忽略的 `tools/.cache/`。

页面运行只读取本地资料和图片，不请求外部 API。脚本仅开发更新数据时需要 Python 与网络，正常运行不需要它。

## 属性与队伍分析

`攻击 → 双属性防御倍率 = 对第一属性的倍率 × 对第二属性的倍率`。

“弱点人数”统计倍率大于 1 的成员；“抵抗人数”统计倍率小于 1 的成员，包含倍率为 0 的免疫成员。成员属性分布允许双属性分别计数，所以分类计数总和可能大于队伍人数。

进化详情只展示本次收录范围内相邻的物种关系；可能不包括后续世代的分支。队伍分析不计入招式、特性、等级、努力值、个体值或其他战斗机制。

## 自定预算与参考队伍

每位成员的配队成本为公开资料中六项基础能力之和，队伍成本为所有成员成本之和。队伍最多 6 位成员，总预算 **3000 点**。该上限是作者为增加配队取舍而设计的项目规则，不是 PokéAPI 提供的字段或官方赛事规则；调整预算也不会修改原始能力数据。

`js/data/challenges.js` 存放作者编排的参考队伍，内容包括主题、成员编号与说明。成员编号关联公开图鉴，能力和属性统计始终由同一份本地资料计算。组合本身是作者创作的挑战素材，不是采集到的玩家队伍，也没有虚构的玩家身份、战绩或受欢迎程度。

当前编辑队伍可与参考队伍或本人保存的队伍比较。比较列出成员数量、总成本、剩余预算、六项基础能力平均值、属性分布与弱点/抵抗人数。人数不同会影响成本与防御人数，应结合人数和平均值阅读；这些指标不等于胜率，也不生成胜负结论。

## 个人数据与素材说明

收藏、队伍和练习成绩来自实际操作。资料快照与个人浏览器记录分开。JSON 导出不包含账号密码，导入只替换当前账号记录。

预算规则加入前已保存的超预算队伍不会自动删除或改写，可载入后通过移除成员等方式调整，符合预算后再保存。导入时按当前规则校验全部内容，若任一队伍超预算则整次拒绝，不部分替换个人记录。
