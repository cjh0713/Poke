# 宝可梦发现室课堂汇报提纲

建议总计约 5 分钟：约 3 分钟说明，约 2 分钟演示。下面是准备稿，按自己实际能解释的内容取舍；没有亲自完成的学习、修改与验证，不说成已经完成。AI 辅助生成的部分也应如实说明。详细架构见 [开发说明](开发说明.md)。

## 约 3 分钟讲清项目

### 0:00—0:35 · 题目与用户

> 我的项目叫宝可梦发现室，面向刚认识角色、还看不懂属性和能力差异的初学者。它从公开图鉴开始，让用户查角色、比较能力，再用属性实验与有限预算配队理解取舍。目标用户首先是我本人和愿意试玩的同学；目前不能把计划中的试玩说成已经做过调研。

### 0:35—1:10 · 数据为什么具体

> 项目限定全国图鉴 001—151 的默认形态。中文名、身高体重、六项基础能力和属性关系来自 PokéAPI 社区资料，图片保存在本地，来源清单记录时间、URL 和摘要。比如皮卡丘的编号是 25，属性是电，六项基础能力总和为 320。这里“初代”指收录范围，数值和属性使用资料快照中的现行规则。

### 1:10—2:00 · 两个主要互动

> 属性实验室左边的小精灵代表一个攻击属性，右边选一只真实图鉴目标。目标有哪一两种属性，直接读取资料。点击发射后，规则函数算出倍率，页面用文字与不同动画表达结果，计算过程可以展开。它演示属性关系，没有完整战斗和血量。
>
> 配队用成员基础能力之和当成本，上限是项目设计的 3000 点。新手任务要求六位不重复成员，并让电属性弱点人数不超过两位。还有四支作者设计的静态参考队伍，可以与当前搭配比较；它们不是其他玩家上传的数据，也不决定谁会赢。

### 2:00—3:00 · 代码组织与学习边界

> 项目使用 HTML、CSS 和原生 JavaScript，不需要构建工具。页面通过 store 接口取资料和保存个人记录，rules 只负责计算，独立的效果模块只负责实验动画。这样即使修改动画，属性倍率也不需要改；以后接后端，主要替换数据访问实现。
>
> 单机版支持本地账号，收藏、保存的队伍和完成的五题练习成绩按账号隔离。实验选择和未保存队伍只存在内存。代码使用 AI 辅助生成，我需要通过阅读、手算、自己修改和解释来证明学习；汇报时只展示我实际理解的函数，并说明还不懂的地方。

最后一句可以结合真实情况补充：“这次我亲自修改了……，用……观察结果；还需要继续理解……。”尚未完成前保留空白，不照着假装说完。

## 约 2 分钟现场演示

| 时间 | 操作 | 同时解释什么 |
|---|---|---|
| 0:00—0:20 | 搜索皮卡丘，打开详情 | 名字、图片、属性和能力条都来自同一条公开记录 |
| 0:20—0:55 | 进入属性实验室，选择岩石攻击与喷火龙，发射并展开计算 | 目标火／飞行自动读取，2 × 2 = 4；动画表达弱点，倍率不是血量伤害 |
| 0:55—1:10 | 改为电属性与小拳石，观察准备状态，再发射 | 旧结果复位；岩石／地面的因子为 1 与 0，最后无效 |
| 1:10—1:40 | 打开“我的队伍”，用一支作者预设开始搭配，查看预算和任务 | 预设是静态参考；任务实时检查三条件，成员变化就重新计算 |
| 1:40—2:00 | 与另一参考队伍对比；若已准备好本地账号，再手动保存自己的队伍 | 比较成本、平均能力和防御人数；手动保存与即时任务状态是两回事 |

演示前先实际走一遍，选择自己熟悉的预设即可。不保证每支参考队伍都满足新手任务，现场按页面结果说明。登录与完整五题练习可提前准备或留到问答，不挤进 2 分钟时限；预设能直接用作起点，不能把未演示操作说成通过验证。

## 常见问答的回答要点

| 可能的问题 | 回答重点 |
|---|---|
| 为什么选这个主题，是否只是游戏？ | 内容是角色公开资料与规则探索；功能围绕初学者理解差异，题材认可由教师判断，不虚构社会调查 |
| 数据是假的吗？ | 角色参数与素材有公开来源；参考组合是作者创作；个人收藏、队伍与练习成绩来自实际操作，三者要分开 |
| 为什么攻击只有一种，防御可以有两种？ | 一次单属性攻击对目标真实防御属性逐项查表，双属性因子相乘；攻击精灵不是要模拟完整出招的角色 |
| 0 倍率为什么要单独判断？ | 免疫是零，需要与普通抵抗区分；例如乘积里有 0，结果仍为 0 |
| 为什么设 3000 点？ | 这是增加配队取舍的自定规则，使用公开基础值计算成本；不是官方赛制，也不能保证实战平衡 |
| 配队任务完成会自动保存吗？ | 不会。任务基于当前草稿实时计算；保存队伍需登录并明确点击，任务不发奖励也不判胜负 |
| 动画出问题会影响计算吗？ | 计算与效果分开，页面先得到规则结果；效果模块只展示、取消和清理，减少动画时仍应能读文字结果 |
| 这是真正的多用户网站吗？ | 是同一浏览器里的本地账号隔离，尚无服务端认证和跨设备共享 |
| 为什么页面不直接 localStorage？ | 集中校验和存储，减少页面重复逻辑，未来接后端时保留调用接口；核心倍率仍单独计算 |
| AI 做了多少，你学到了什么？ | 如实说明辅助范围，再用本人确实读过或修改过的函数演示；不能用文档或测试通过替代理解 |

## 汇报前需要亲自完成的练习

1. 用本地资料找到皮卡丘记录，手算 `35 + 55 + 40 + 50 + 50 + 90 = 320`，指出卡片、详情和预算各在哪里使用它。
2. 手算岩石→喷火龙的 `2 × 2`、火→喷火龙的 `0.5 × 1`、一般→皮卡丘的 `1`、电→小拳石的 `1 × 0`，再到页面核对四种反馈。
3. 追踪一次发射：选择事件更新什么状态，`typeExperiment()` 返回什么，哪些代码只改变 DOM 动效，哪些内容不写 localStorage。
4. 给队伍增删一位成员，解释成本与电弱点人数怎样变化；观察任务完成和手动保存的区别。
5. 用两个本地账号各保存一条不同记录并刷新，确认自己能解释记录如何隔离；先导出备份，再在需要的情况下尝试导入。
6. 独立修改一条台词或一个样式值，用自己的话记录修改目的和实际现象。仍不清楚的地方写成问题，课堂上诚实说明。
